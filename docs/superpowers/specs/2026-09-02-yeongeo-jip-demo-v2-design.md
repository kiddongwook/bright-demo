# 영어의 집 — 데모 v2 설계 (1단계: 데모 재구성)

작성 2026-09-02 · 상태: 승인됨 (대화에서 구두 승인)

## 1. 배경

원장 미팅에서 받은 답:

> 출결관리, 공지사항, Q&A, 학원 등원생 및 학부모만 제한적 입장 기능 정도를
> 기본으로 하고, 확장성 있게 추가되는 느낌이면 좋겠다.

현재 데모(한빛영어학원, `afe6bd8`)는 AI 첨삭·편지·성장 기록·수강료가 중심이고,
원장이 말한 기본 4개 중 **출결만** 있다. 공지·Q&A·입장 제한은 없다.
로고(「영어의 집」, 가는 선 집 + 워드마크)를 받았고, UI를 로고에 맞춰 다시 잡기로 했다.

## 2. 목표

원장이 말한 기본 4개를 **화면으로 증명**하는 정적 데모. 백엔드 없이 GitHub Pages 배포.
원장이 이 화면을 보고 "이거다"라고 하면 2단계(실제 구축)로 간다.

## 3. 범위

### 포함 (1단계)
- 입장 게이트(목업) + 역할 3개(원장·학부모·학생)의 앱
- 기본 4개: 출결 · 공지 · 문의(자주 묻는 질문 + 1:1) · 입장 제한
- 알림(종 아이콘 + 토스트)
- 더보기의 확장 영역("준비 중" 모듈)
- 로고 기준 디자인 재정립
- 로고 자산 정리, `영어의 집`으로 이름 교체, og.png 재생성
- 검증: 셸 테스트 갱신, 3역할 스크린샷, 390px 실측

### 제외 (2단계 이후)
- 실제 인증·백엔드·데이터 저장
- 실제 푸시/알림톡 발송
- 학생의 문의 기능
- AI 첨삭·편지·성장 기록·수강료의 실제 동작 (더보기에 "준비 중"으로만 표시)

## 4. 결정 사항 (원장·사용자 답)

| 항목 | 결정 |
|---|---|
| 진행 순서 | 데모 재구성 먼저 → 원장 확인 → 실제 구축 |
| Q&A 형태 | 자주 묻는 질문 목록(원장이 정리) + 그 아래 1:1 비공개 문의 |
| 입장 제한 | 원장이 명부에 등록한 전화번호로만 가입 (인증번호) |

| 학원 강조색 | **미정.** 로고 마스터는 흑백. 원장이 6개 컬러웨이 중 고를 때까지 먹(단색) |

## 5. 구조

### 5.1 입장 게이트 (`g-*`)
```
g-phone   전화번호 입력
          → 명부에 있으면 g-code, 없으면 g-deny
g-code    인증번호 입력 → 역할 자동 결정 → 해당 앱으로
g-deny    "명부에 없는 번호입니다. 원장님께 등록을 요청하세요."
```
데모 편의: `g-phone` 화면 하단에 "데모로 들어가기" 영역을 두고 원장·학부모·학생 번호 셋을 보여준다.
누르면 번호가 채워지고 다음 단계로 간다. 아무 번호나 치면 `g-deny`.

### 5.2 역할별 탭
```
원장    오늘(출결) · 공지 · 문의 · 더보기
학부모  우리 아이(출결) · 공지 · 문의 · 더보기
학생    나(출결) · 공지 · 더보기
```
탭바는 역할에 따라 3~4개. 앱바 오른쪽에 알림 종(숫자 배지).

## 11. v2.1 — 상태 연결 (2026-09-02 추가)

원장 확인 전 고도화. 화면을 토스트로 끝내지 않고 **역할 간에 데이터가 이어지게** 한다.

- `DB` 객체 하나가 공지·문의·오늘 출결·알림을 든다. 이 객체가 2단계 백엔드 스키마의 초안이다.
- 그리기 함수(`rNotices/rInbox/rNoti/rAtt/rNoticeView/rAnswer`)가 매 `render()`마다 상태에서 화면을 다시 그린다.
- 행동 함수: `postNotice`(원장 공지 → 대상 학부모·학생 알림), `openNotice`(학부모·학생이 열면 읽음 +1),
  `sendAsk`(학부모 문의 → 원장 알림·문의함), `openAsk`/`sendAnswer`(원장 답변 → 그 학부모 알림),
  `att`/`saveAtt`(원장 출결 저장 → 학생 화면·알림).
- 알림 화면을 열면 읽음 처리, 배지는 미읽음 수.
- 상태는 메모리에만. 원장 더보기에 「데모 처음 상태로」(새로고침).
- 검증: 셸 테스트에 상태 연결 블록 — 공지 올린 뒤 학부모 목록 +1·배지 3, 열람 후 읽음 1,
  문의 후 원장 미답변 2·배지 2, 답변 후 학부모 배지 4·내 문의에 답변, 결석 저장 후 학생 태그 「결석」·배지 3.

## 12. v2.2 — 결석 사전 신청 + 보강 (2026-09-02 추가)

출결관리를 "오늘 찍기"에서 "앞으로의 결석까지"로 넓힌다. FAQ가 약속한 "사전 결석은 보강"의 실제 경로.

- 학부모 「우리 아이」에 **미리 알린 결석** 목록 + 「결석 미리 알리기」(`p-absence`: 수업일 3개 중 택1 + 사유).
- 보내면 `DB.absences`에 `요청`으로 들어가고 원장 알림. 학부모 주간 표에 그 요일이 ✕(결석 예정)로 표시.
- 원장 「오늘」에 **결석 신청** 목록(요청 먼저, 처리됨 아래). 누르면 `d-makeup`: 보강 후보(토요일 2시 두 개, 자료로 대체) 중 택1 → 「확정하고 알리기」.
- 확정하면 `보강 확정` + 학부모 알림. 학부모 주간 표에 보강일이 ◌(점선)으로 표시.
- 씨앗: 최유나 6월 20일 금 `요청`(원장 목록에 1건), 한지우 6월 12일 목 → 6월 14일 토 보강(처리됨 예시). 학부모 본인 것은 없음 → 빈 상태 문구.
- 검증: 셸 테스트에 결석 블록 — 신청 후 주간 표 ✕, 원장 요청 2건, 보강 확정 후 학부모 배지 +1·목록에 보강일·주간 표 ◌.
- 학생 화면은 손대지 않음(고등이라 학생 본인 신청도 후보지만 이번엔 학부모만).

## 13. v2.3 — 학생 「이번 주 할 것」 (2026-09-02 추가)

고등학생이 앱을 열 이유. 학생 「나」 맨 위에 이번 주 숙제·시험 목록, 했으면 동그라미를 눌러 체크.
시험 항목은 공지에 연결(누르면 공지 상세). 학부모 「우리 아이」에 같은 목록을 읽기 전용으로.

- `DB.todos` — {cls, kind(숙제|시험), title, due, done, notice?}. 씨앗: 고2 B 3개(1개 완료), 고1 A 2개(1개 완료).
- `rTodos()`가 학생 목록(체크 가능)과 학부모 목록(읽기 전용)을 그리고, 남은 개수를 「N개 남음 / 다 했어요」로.
- `toggleTodo(id)` — 상태 토글 + 토스트. 원장 쪽은 손대지 않음(숙제 완료 집계는 후보).
- 입장 문구를 "문을 열어드릴게요"로 (제한 안내문 톤 제거).
- 검증: 학생 3개·완료 1·「2개 남음」 → 토글 후 완료 2·「1개 남음」, 학부모 목록 ≥1.

## 14. v2.4 — 공지 안 읽은 사람 다시 알리기 (2026-09-02 추가)

원장이 알고 싶은 건 읽은 *수*가 아니라 *누가 안 읽었나*.

- 공지의 `read` 수를 `readers`(학부모 이름 목록)로 바꾼다. 대상(`all`/`A`/`B`)별 학부모 명단 `PARENTS`에서 안 읽은 사람 = 대상 − readers.
- 원장 공지 목록의 행을 누르면 `d-readers`: 안 읽음 / 읽음 명단, 「안 읽은 N명에게 다시 알리기」.
- 다시 알리면 `remindedAt` 기록, 데모 학부모가 안 읽은 쪽이면 학부모 알림 「아직 안 읽으셨어요」. 목록에 「다시 알림」 표시.
- 학부모가 공지를 열면 readers에 이름이 들어간다(기존 readP 유지).
- 검증: 여름 특강(전체) 안 읽음 2·읽음 4 → 다시 알리기 → 학부모 배지 +1, 알림에 「아직」.

## 15. v2.5 — 학부모 카톡 알림 미리보기 (2026-09-02 추가)

편의성 주장의 핵심 증거: 학부모는 앱을 안 열어도 카톡으로 받고, 누르면 그 화면이 열린다.

- `DB.outbox` 발송함 — 학부모 카톡으로 나간 것 {to, kind, title, text, link:[뷰, id], at}. 씨앗 3건.
- 알림을 보내는 행동 5개(공지·답변·보강 확정·다시 알리기·출결 저장)가 `sendOut()`으로 한 줄씩 남긴다.
- 원장 「더보기」→「학부모 카톡에는 이렇게 도착해요」(`d-kakao`): 카톡 대화창 모양에 알림톡 카드. 데모 학부모 앞으로 온 카드의 「앱에서 보기」를 누르면 실제로 학부모 앱의 그 화면으로 넘어간다(`kakaoOpen`).
- 문구는 알림톡 템플릿처럼 짧고 정형 — 2단계에서 "데모와 다르다"가 안 나오게. 화면 하단에 그 설명.
- 검증: 씨앗 카드 3 → 공지 올린 뒤 발송함 4·카드 4 → 「앱에서 보기」 → 학부모 공지 상세에 그 제목.
