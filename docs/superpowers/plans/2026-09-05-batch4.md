# 4차 묶음 — 정리 마감 + 사용성 고도화 Implementation Plan

**Goal:** 사장님이 고른 순서대로 끝까지. 정리(잠금 구멍·약관 동의·설명서) → 큰 글씨 → 공지 예약 발송 → 수강료 자동화 → 학부모 주간 요약. 결정: **영어의 집은 기본 학원으로 유지**(slug `yeongeo` 시연 데이터도 그대로, DEFAULT_SLUG 유지).

**Architecture:** 마이그레이션 번호 선점 — 0026 동의, 0027 공지 예약, 0028 수강료 자동, 0029 주간 요약. 크론은 사용자 컨텍스트가 없으므로 `*_for(academy, …)` 내부 함수(authenticated 에서 revoke)와 원장용 얇은 래퍼로 나눈다. 학원 단위 설정은 원장이 쓸 수 있는 표(`billing_rules`·`academies`)에 둔다 — `academy_settings` 는 RLS 정책이 없어 운영자 전용. 동시 작업 충돌을 피해 기능별 클라이언트 함수는 각자 파일(`lib/noticeSchedule.ts`, `lib/billingAuto.ts`, `lib/weekly.ts`)에 두고, `cleanup-test-data.mjs` 접두어(`sched-`, `auto-`, `wk-`, `consent-`)는 Fable 이 마지막에 넣는다.

## 1차 물결 (파일 겹침 없음, 동시 진행)

### T1 잠금 마감 (Edge 만)
- `otp-send`: `_shared/auth.ts` 41–45 와 같은 필터 — `roster_phones … academies(locked)`, 잠긴 학원 행은 뺀다. 남는 학원이 없고 운영자도 아니면 403 `academy_locked` (문자를 보내지 않는다). `Otp.tsx` 보내기 단계 오류 지도에 `academy_locked` → `LOCKED`.
- `link-login`: `lt.academy_id` 의 `academies.locked` 가 true 면 403 `academy_locked`. `LinkEntry.tsx` 가 `LOCKED` 문구로 안내.
- `tools/operator-test.mjs`: 잠금 뒤 `otp-send` 403·`link-login` 403 두 단계 추가.

### T2 약관·개인정보 동의 (0026)
- `consents(user_id pk → users on delete cascade, terms_version text, privacy_version text, agreed_at timestamptz)`. RPC `accept_terms(p_terms text, p_privacy text)`(auth.uid() 로 upsert), `my_consent()` returns (terms_version, privacy_version). RLS: 본인 행만 select.
- 문서 `docs/legal/terms.md`, `docs/legal/privacy.md`(둘 다 첫 줄에 "변호사 검토 전 초안") — 학원이 **개인정보처리자**, BRIGHT 는 **수탁자**(원장이 명부 번호를 올린다). 14세 미만 학생은 법정대리인 동의 — 학부모 로그인 경로에 명시. 정적 `legal/terms.html`, `legal/privacy.html` 을 저장소 루트에(랜딩 `index.html` 풋터·앱 About 에 링크).
- 앱: `lib/legal.ts` 에 `TERMS_VERSION`, `PRIVACY_VERSION`, 본문 요약. `screens/Consent.tsx` — 로그인 뒤 `my_consent` 가 없거나 버전이 낮으면 한 번 뜬다(필수 체크 2개, "동의하고 시작"). 제한 세션(알림톡 링크)은 건너뛴다; 운영자도 동의한다. UX 게이트일 뿐 RLS 강제는 아님(문서에 적는다).

### T3 큰 글씨 + 화면 설정 (클라이언트만)
- 레이아웃이 vh·safe-area 를 25곳 쓰므로 `zoom` 은 쓰지 않는다. 글자만: 스크립트로 `font-size: Npx` → `calc(Npx * var(--fs))` 일괄 치환(theme.css·screens/*.css·components), `:root{--fs:1}`, `html[data-text=large]{--fs:1.15}`. `lib/theme.ts` 에 `textScale` 읽기/쓰기(localStorage `text`), 부팅 시 적용.
- `Prefs.tsx` 에 "화면" 묶음: 글자 크기(보통/크게), 테마(기기 따라/밝게/어둡게 — 기존 localStorage.theme 수동 지정 사용). 좁은 자리(탭바·칩·타일·수강료 표) 넘침 점검용으로 `sweep.mjs` 에 large 모드 한 바퀴 추가.

## 2차 물결 (마이그레이션·화면 분리, 동시 진행)

### T4 공지 예약 발송 (0027)
- `notices.publish_at timestamptz not null default now()`, `notices.fanned_at timestamptz`. 뿌리기 본체를 `notice_fanout(nid)` 로 뽑고(안에서 `fanned_at` 을 찍어 두 번 못 나가게), 제약 트리거는 `publish_at <= now()` 일 때만 부른다. `publish_due_notices()` 를 매분 크론으로 — `publish_at <= now() and fanned_at is null` 인 것을 뿌린다.
- `create_notice_v2(text,text,uuid[])` 는 **drop 후** 4 인자(`p_publish_at timestamptz default null`)로 다시 만들고 revoke/grant 재발급. `reschedule_notice(nid, p_publish_at)`(스태프, 아직 안 나간 것만), 삭제는 기존 정책.
- 보이기: 스태프가 아니면 `publish_at > now()` 인 공지는 `notice_visible_of` 에서 false. 다른 읽기 길(`notice_targets_read`, `notice_reads`, `notice_readers`, todos.notice_id) 도 같은 조건. **휴원일 연동 결정:** 휴원 공지를 예약해도 휴원일은 작성 시점에 바로 달력에 들어간다(휴원은 사실이고 학부모가 미리 알수록 좋다).
- 화면(`Notices.tsx`): 보내기 줄 — "지금" / "예약"(DateField+TimeField, 기본 다음날 08:00). 목록에 "예약 · 9/6 08:00" 배지, 눌러 시트: 시간 바꾸기 / 지금 보내기 / 삭제. 읽음률 도넛은 예약 상태에서 숨김.
- 테스트 `tools/notice-schedule-test.mjs`(접두어 `sched-`): 예약 → 학부모 안 보임·알림 없음 → 크론 함수 직접 호출 → 보임·알림 1건 → 재호출해도 추가 없음.

### T5 수강료 자동화 (0028)
- `billing_rules` 에 `auto_issue boolean default false`, `auto_remind boolean default false`, `auto_remind_after_days int default 3 check 1..14` (발행일은 기존 `billing_day`). 원장 정책 그대로 쓸 수 있다.
- `issue_invoices_for(a, ym)` / `remind_unpaid_for(a, ym)` 내부 함수로 본체 이동(authenticated revoke), 기존 두 함수는 원장 검사 뒤 위임. `billing_tick()` 매일 00:00 UTC(09:00 KST): `auto_issue` 이고 KST 오늘 일자 = `billing_day` 인 학원은 이번 달 발행(unique 가 중복 방지) → 원장 알림 "N건 발행"; `auto_remind` 이고 납기 + after_days 지난 미납은 안내(기존 20시간 창) → 원장 알림 "N명에게 안내".
- 화면 `BillingSettings.tsx`: "자동" 묶음 — 자동 발행(매월 billing_day 일) 토글, 자동 미납 안내 토글 + N일 뒤. 설명 한 줄: "발행하면 학부모 수강료 카드에 바로 보여요".
- 테스트 `tools/billing-auto-test.mjs`(접두어 `auto-`): 같은 날 두 번 tick → 발행 1회, 퇴원생 제외, 미납 안내 dedupe.

### T6 학부모 주간 요약 (0029)
- `academies` 에 `weekly_summary boolean default true`, `weekly_dow int default 5`, `weekly_hour int default 18`, `weekly_last_at timestamptz` (원장은 academies_write 로 수정). 학부모 개인 끄기는 prefs jsonb `weekly`(기본 true).
- `weekly_summary_tick()` 매시: KST 요일·시가 맞고 `weekly_last_at` 이 이번 주 이전인 학원마다 — 학부모(학생 있는 membership)별 알림 kind `weekly`: "이번 주 지훈이 · 출석 3 지각 1 결석 0 · 숙제 2/3 · 다음 수업 월 19:00(휴원 있으면 표시)" 링크 `child:`; 원장에게 "이번 주 출석률 92% · 미납 2건". 0022 알림 트리거 매핑에 `weekly` → 코드 `WEEKLY`, `k := null`(푸시만, 알림톡 비용 없음). 본문 120자 안.
- 화면: 학부모 `Prefs.tsx` "주간 요약 받기" 토글(2차 물결에서 Prefs 를 만지는 건 T6 만); 원장 `우리 학원`(director/More.tsx) 에 "주간 요약 · 금 18:00" 행(요일·시 선택, 끄기).
- 테스트 `tools/weekly-test.mjs`(접두어 `wk-`): 출결·숙제 심고 tick → 알림 본문 숫자 일치, push outbox 만 생김(alimtalk 없음), 같은 시간 재호출 무발송.
