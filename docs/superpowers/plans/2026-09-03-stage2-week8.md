# 2단계 8주차 Implementation Plan — 마지막 주: 공지 사진 · 학원 로고 · 아직 안 들어온 사람 · 숙제 검사 · 출결표 내려받기 · 2단계 마무리

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 2단계(스펙 §8, 8주)를 닫는다. 파일럿 첫 주에 원장이 바로 찾을 다섯 가지를 채우고 — 사진이 붙는 공지, 우리 학원 로고, "누가 아직 앱에 안 들어왔나"와 초대 다시 보내기, 숙제를 원장이 대신 체크(숙제 검사), 반별 출결표 CSV — 남은 것은 3단계 목록으로 넘긴다.

**Architecture:** 파일은 Supabase Storage 두 버킷 — `notices`(비공개, 경로 `<academy_id>/<notice_id>/<n>.jpg`, 같은 학원만 읽기·staff 만 쓰기, 화면은 서명 URL 1시간) 와 `logos`(공개 읽기, 경로 `<academy_id>/logo.png`, 원장만 쓰기). 사진은 브라우저에서 canvas 로 긴 변 1600px·JPEG 0.85 로 줄여 올린다(공지당 3장). 로고는 512px 정사각 PNG. "아직 안 들어온 사람"은 RPC `roster_entry_status()` 하나(명부 행 × 사용자 유무). 숙제 검사는 `todo_done` 에 staff 정책을 더해 원장이 학생 대신 체크. 출결표 CSV 는 브라우저에서 만든다(BOM 붙여 엑셀 호환).

**Tech Stack:** 1~7주차와 동일 + Supabase Storage(JS 클라이언트 `supabase.storage`). DB·Storage 정책은 **에이전트 DB 가 본 트리에서 먼저**(0011 + 테스트), 화면 넷은 워크트리에서 병렬, Fable 이 합친다.

## Global Constraints

- 1~7주차 전역 제약 그대로. 마이그레이션은 `0011_files.sql` 추가만. 버킷 생성은 마이그레이션 안에서 `insert into storage.buckets` 로(대시보드 손작업 없이 재현 가능하게).
- 사진·로고에 원본 파일명·EXIF 를 남기지 않는다(canvas 재인코딩이 EXIF 를 지운다). 공지 사진은 공지를 지우면 같이 지운다(앱에서 `storage.remove`).
- 공지 사진은 **앱 안에서만** 본다. 알림톡 문구·outbox 는 바뀌지 않는다.
- 내려받기(CSV)는 원장·강사 화면에서만, 학부모에겐 없다.
- 에이전트는 worktree 브랜치에만 커밋, push 금지, `.env.local` 값 출력 금지, `cleanup-test-data.mjs` 실행 금지(Fable 이 마지막에 한 번).

### Task 1 (DB): `0011_files.sql` — 버킷·정책·RPC

**Files:** Create `supabase/migrations/0011_files.sql`, `tools/files-test.mjs`; Modify `tools/manage-test.mjs`(K 절), `tools/cleanup-test-data.mjs`(slug `files-%`)

**Interfaces (Produces):**
- `insert into storage.buckets (id, name, public, file_size_limit, allowed_mime_types) values ('notices','notices',false, 5242880, '{image/jpeg,image/png}'), ('logos','logos',true, 1048576, '{image/png,image/jpeg}') on conflict (id) do nothing;`
- Storage 정책(`storage.objects`): `notices_read` select — `bucket_id='notices' and (storage.foldername(name))[1] = current_academy_id()::text`; `notices_write` insert/update/delete — 같은 조건 + `is_staff()`. `logos_write` insert/update/delete — `bucket_id='logos' and (storage.foldername(name))[1] = current_academy_id()::text and current_role_()='director'`; 읽기는 public 버킷이라 정책 불필요.
- `alter table notices add column if not exists photos jsonb not null default '[]'::jsonb;` (경로 문자열 배열).
- `roster_entry_status() returns table (role user_role, name text, phone text, student_name text, entered boolean)` — staff 전용(`is_staff()` 아니면 예외). `roster_phones` × `users`(phone) × `memberships`(같은 학원·같은 role·같은 student_id) — entered = membership 존재. 원장·강사 행은 제외(학부모·학생만).
- `todo_done_staff` 정책: `for all using (todo_id in (select id from todos where class_id in (select staff_class_ids()))) with check (같은 조건)`.
- `public_academy(p_slug)` 를 `returns table (name text, brand_color text, logo_path text)` 로 교체(0010 것 drop 후 create — 반환형이 바뀌므로 `drop function public_academy(text)` 먼저).
