# 2단계 7주차 Implementation Plan — 파일럿 여유분: 빠진 조각 채우기 (할 것 관리 · 알림 설정 · 학원 이름 분리 · 요일별 시간 · 실제 갱신 확인)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 파일럿을 돌리면 바로 부딪힐 네 가지 빈 곳을 메운다 — (1) 학생 화면의 "이번 주 할 것"을 **원장·강사가 넣을 수 있는 화면이 없다**(씨앗으로만 채워져 있다), (2) 학부모 더보기의 "알림 설정"이 "다음 주에 열려요" 토스트로 남아 있다, (3) 문·인증·알림톡 문구에 "영어의 집"이 박혀 있어 두 번째 학원을 열 수 없다, (4) 반 시간표가 요일마다 같은 시간만 된다. 그리고 실제 주소에서 "새 버전" 배너가 실제로 뜨는지 확인한다.

**Architecture:** 할 것은 이미 있는 `todos`·`todo_done` 표를 그대로 쓰고 원장·강사용 화면(`todos`)만 붙인다(반별 · 다가오는 것 · 추가·삭제 · 반 완료 현황). 알림 설정은 `users.prefs jsonb`(기본 전부 켬) 하나로, **앱 안 알림은 항상 남기고 카톡(outbox)만** 끈다 — `trg_notification_outbox` 가 받는 사람의 prefs 를 본다. 학원 이름 분리는 `academies.slug` 를 URL `?a=<slug>`(없으면 마지막 값·기본 `yeongeo`)로 받아 **문·인증 화면 문구와 알림톡 `[학원]` 변수**에 넣는다(로고 이미지·매니페스트는 파일럿 학원 것 그대로 — 로고 업로드는 3단계). 요일별 시간은 `classes.schedule` 이 이미 요일별 배열이라 폼만 바꾼다.

**Tech Stack:** 1~6주차와 동일. 구현은 작업별 에이전트가 **git worktree** 에서 하고(서로 `api.ts`·`registry.tsx`·`nav.tsx` 를 건드리므로), Fable 이 순서대로 main 에 합치며 충돌을 푼다.

## Global Constraints

- 1~6주차 전역 제약 그대로. 마이그레이션은 `0010_prefs.sql` 추가만.
- 알림 설정을 꺼도 **앱 안 알림·종 배지는 그대로**. 끄는 건 카톡(과 문자 대체)뿐. 원장 대상 알림(문의 접수·결석 신청)은 설정 대상이 아니다(카톡을 안 보낸다).
- 학원 이름은 DB(`academies.name`)에서만 온다. 새 하드코딩 금지. 알림톡 문구는 `[#{학원}]` 변수로 바꾸고 `docs/ops/alimtalk.md` 표도 같이 바꾼다(아직 심사 전).
- 할 것은 `class_id` 기준(반 전체). 개인별 할 것은 범위 밖.
- 에이전트는 자기 worktree 브랜치에만 커밋하고 push 하지 않는다. `.env.local` 값은 절대 출력하지 않는다.

### Task 3 (B): 알림 설정 + 알림톡 `[학원]` 변수 + `public_academy` RPC

**Files:** Create `supabase/migrations/0010_prefs.sql`, `app/src/screens/shared/Prefs.tsx`; Modify `supabase/functions/_shared/alimtalk.ts`, `supabase/functions/otp-send/index.ts`, `supabase/functions/outbox-send/index.ts`(params 에 `학원` 을 넣는다), `app/src/lib/api.ts`(`getPrefs`·`setPrefs`), `shared/More.tsx`("알림 설정" 행 → `prefs`), `registry.tsx`(`*:prefs`), `nav.tsx`(`TITLE.prefs = ['알림 설정', '']`, `PARENT_TAB.prefs = 'more'`), `tools/outbox-test.mjs`(F 절), `docs/ops/alimtalk.md`

**Interfaces (Produces):**
- `0010_prefs.sql`:
  - `alter table users add column prefs jsonb not null default '{}'::jsonb;` — 키: `kakao_notice`·`kakao_remind`·`kakao_answer`·`kakao_makeup`·`kakao_attendance` (없으면 true).
  - `users_self_upd` 정책은 이미 본인 update 를 허용한다 — 앱은 `update users set prefs = …` 만 한다.
  - `trg_notification_outbox()` 교체: 코드 결정 뒤 `select prefs into p_prefs from users where id = new.user_id;` 하고 해당 키가 `false` 면 `return new`(outbox 에 넣지 않음). 키 매핑: NOTICE_NEW→kakao_notice, NOTICE_REMIND→kakao_remind, INQUIRY_ANSWERED→kakao_answer, MAKEUP_CONFIRMED→kakao_makeup, ATTENDANCE→kakao_attendance.
  - outbox `params` 에 `'학원', (select name from academies where id = new.academy_id)` 를 항상 넣는다(5 템플릿 모두).
  - `create or replace function public_academy(p_slug text) returns table (name text, brand_color text) language sql stable security definer set search_path = public as $$ select name, brand_color from academies where slug = p_slug $$; grant execute on function public_academy(text) to anon, authenticated;` — 문 화면이 로그인 전에 부른다.
- `alimtalk.ts` `TEMPLATES` 문구를 `[${p['학원'] ?? '학원'}] …` 로(5개), `renderSms` 동일. `otp-send` 문자도 `[${학원명}]` — `roster_phones` 대조 때 `academies.name` 을 같이 읽는다(번호가 여러 학원에 있으면 첫 학원).
- 앱 `getPrefs(): Promise<Record<string, boolean>>`(users.prefs), `setPrefs(p)`; 화면 `Prefs`: 다섯 토글(`.rw` + 체크 표시 `.cb`), 안내 "앱 안 알림은 계속 남아요. 카톡만 끄는 거예요", 저장 즉시(`setPrefs`), toast.
- outbox-test F: 학부모가 `prefs = {kakao_attendance:false}` 로 update → 지각 attendance insert → 알림은 생기고(notifications 1) outbox 는 안 생김; `prefs` 되돌리면 생김. 그리고 B 절의 debug 항목 `params` 확인은 없으니 `outbox` 행의 `params->>'학원'` 이 학원 이름인지 한 줄.
- `docs/ops/alimtalk.md` 표를 `[#{학원}] …` 로, 변수 목록에 `학원` 추가.

### Task 4 (C, B 뒤): 학원 이름 분리 (slug)

**Files:** Create `app/src/lib/academy.ts`; Modify `Gate.tsx`, `Otp.tsx`, `LinkEntry.tsx`, `App.tsx`(문서 title), `director/More.tsx`(초대 문구 주소 끝에 `?a=<slug>`), `docs/ops/pilot.md`

**Interfaces (Produces):**
```ts
// lib/academy.ts
export const DEFAULT_SLUG = 'yeongeo';
export function currentSlug(): string   // location.search 의 a= → localStorage 'academy_slug' 에 저장 → 없으면 저장된 값 → 없으면 DEFAULT_SLUG
export async function publicAcademy(slug: string): Promise<{ name: string; brand_color: string } | null>   // rpc public_academy
```
- `Gate`: 마운트 때 `publicAcademy(currentSlug())` → 이름을 문구에(`{name} 학생·학부모로 등록된 전화번호를 알려주세요`, 404 문구도), `--brand` 도 로그인 전에 적용. slug 가 없는 학원이면 "학원을 찾을 수 없어요. 원장님께 받은 주소로 들어와 주세요".
- `Otp`·`LinkEntry` 의 `alt` 텍스트와 `document.title` 을 이름으로. 로고 이미지는 그대로(파일럿 학원). 
- 초대 문구: 주소를 `${origin}${BASE_URL}?a=${slug}` 로 — slug 는 `academy()` 의 `slug`.
- `pilot.md`: 개설 뒤 학부모에게 주는 주소는 `…/pwa/?a=<slug>` 라고 한 줄.
- 검증: `?a=yeongeo` → "영어의 집"; `?a=없는slug` → 안내 문구; `tools/new-academy.mjs` 로 만든 학원 slug → 그 이름(테스트 뒤 cleanup).
