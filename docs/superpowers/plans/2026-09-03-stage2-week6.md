# 2단계 6주차 Implementation Plan — 파일럿 준비: 실제 주소 확인 · 살림 정리(cron) · 오류 보고·진단 · 온보딩/리셋 도구 · 학부모 초대 · 파일럿 런북

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 영어의 집 원장님이 실제로 쓰기 시작해도 되는 상태로 만든다 — 실제 주소에서 로그인이 되고 알림톡 링크가 그 주소를 가리키며, 표가 쌓이지 않게 매일 정리되고, 앱에서 난 오류가 서버에 남아 원격에서 볼 수 있고, 학원 하나를 새로 열거나(온보딩) 씨앗을 비우고 실제 명부로 바꾸는(리셋) 스크립트가 있고, 학부모에게 보낼 초대 문구가 앱 안에 있으며, 원장이 파일럿을 시작·유지하는 절차가 문서 한 장에 있다.

**Architecture:** 살림은 `housekeeping()` 함수 하나를 `pg_cron` 이 매일 04:00 KST 에 부른다(만료 OTP·토큰, 90일 지난 읽은 알림·보낸 outbox). 오류 보고는 `client_errors` 표(본인 insert 만 허용, 읽기는 없음 — 대시보드 SQL 로 본다)에 앱이 `window.onerror`·`unhandledrejection`·`errToast` 경로에서 적는다(버전·화면·환경 포함, 1분에 5건 상한). 진단 화면은 서버를 만지지 않고 브라우저 안 상태(버전·환경·서비스워커·세션·연결)만 보여 준다. 온보딩·리셋은 서비스 키 스크립트(`tools/`), 리셋은 `SEED_DEMO_WIPE=1` 과 slug 재입력 두 겹 확인.

**Tech Stack:** 1~5주차와 동일. 빌드 시각은 `vite.config.ts` 의 `define: { __BUILD__ }`.

## Global Constraints

- 1~5주차 전역 제약 그대로. 마이그레이션은 `0009_housekeeping.sql` 추가만.
- 살림은 **지우기만** 하고 어떤 학원 데이터(출결·공지·문의·메모)도 건드리지 않는다. 알림은 **읽은 것만**, outbox 는 `sent|delivered` 만, 90일 기준.
- 오류 보고에 개인정보·토큰을 싣지 않는다(메시지·스택 앞 1,000자·화면 이름·버전·UA 만).
- 리셋 스크립트는 `SEED_DEMO_WIPE=1` 없이는 아무것도 지우지 않고, 지울 학원 slug 를 인자로 받아 화면에 학생 수를 보여 준 뒤 같은 slug 를 한 번 더 입력받는다(stdin).
- 실제 주소 `https://kiddongwook.github.io/bright-demo/pwa/` 는 도메인 확보 전 임시. 문서마다 그렇게 적는다.

### Task 2: `0009_housekeeping.sql` — 살림 · 오류 보고 표

**Files:** Create `supabase/migrations/0009_housekeeping.sql`, `tools/housekeeping-test.mjs`; Modify `tools/cleanup-test-data.mjs`(slug `hk-%`)

**Interfaces (Produces):**
- `client_errors(id, academy_id null, user_id null, at, version, screen, env, message, stack, ua)` — RLS: `insert` 은 `auth.uid() = user_id` 또는 `user_id is null`(로그인 전 오류도 받는다), select 정책 없음(service role 만).
- `housekeeping() returns table (what text, n int)` — security definer. 삭제: `otp_codes` where `created_at < now() - 1 day`; `link_tokens` where `expires_at < now() - 7 days`; `notifications` where `read_at is not null and created_at < now() - 90 days`; `outbox` where `status in ('sent','delivered') and created_at < now() - 90 days`; `client_errors` where `at < now() - 30 days`. `revoke execute … from public, anon, authenticated`.
- `cron.schedule('housekeeping-daily', '0 19 * * *', 'select housekeeping()')` (19:00 UTC = 04:00 KST).

- [ ] Step 1: 테스트 `tools/housekeeping-test.mjs` — 학원 `hk-<rnd>`·원장·학부모 만들고 admin 으로 옛 행 심기(otp 2일 전, link_token 만료 8일 전, 읽은 알림 100일 전, 안 읽은 알림 100일 전, outbox sent 100일 전, outbox queued 100일 전, client_errors 40일 전)와 최근 행 하나씩 → `admin.rpc('housekeeping')` → 결과 표의 n 과 남은 행 검증(안 읽은 알림·queued outbox·최근 행은 남는다). 학부모 세션으로 `client_errors` insert(자기 user_id) 성공, 남의 user_id 는 실패, select 는 0행.
- [ ] Step 2: 실패 확인 → Step 3: 마이그레이션 →
```sql
create table if not exists client_errors (
  id uuid primary key default gen_random_uuid(),
  academy_id uuid references academies(id) on delete cascade, user_id uuid references users(id) on delete cascade,
  at timestamptz not null default now(), version text, screen text, env text, message text not null, stack text, ua text);
alter table client_errors enable row level security;
create policy client_errors_ins on client_errors for insert with check (user_id is null or user_id = auth.uid());
create index on client_errors (at);
create or replace function housekeeping() returns table (what text, n int) language plpgsql security definer set search_path = public as $$
declare c int;
begin
  delete from otp_codes where created_at < now() - interval '1 day'; get diagnostics c = row_count; what := 'otp_codes'; n := c; return next;
  delete from link_tokens where expires_at < now() - interval '7 days'; get diagnostics c = row_count; what := 'link_tokens'; n := c; return next;
  delete from notifications where read_at is not null and created_at < now() - interval '90 days'; get diagnostics c = row_count; what := 'notifications'; n := c; return next;
  delete from outbox where status in ('sent','delivered') and created_at < now() - interval '90 days'; get diagnostics c = row_count; what := 'outbox'; n := c; return next;
  delete from client_errors where at < now() - interval '30 days'; get diagnostics c = row_count; what := 'client_errors'; n := c; return next;
end $$;
revoke execute on function housekeeping() from public, anon, authenticated;
select cron.unschedule('housekeeping-daily') where exists (select 1 from cron.job where jobname = 'housekeeping-daily');
select cron.schedule('housekeeping-daily', '0 19 * * *', 'select housekeeping()');
```
(`link_tokens` 를 지우면 `outbox.link_token_id` FK 가 걸린다 — `outbox.link_token_id` 는 `references link_tokens(id)` 이므로 먼저 `update outbox set link_token_id = null where link_token_id in (…)` 하거나 FK 를 `on delete set null` 로 바꾼다. 0009 에서 `alter table outbox drop constraint …, add … on delete set null` — 제약 이름은 `pg_constraint` 에서 찾는 DO 블록.)
